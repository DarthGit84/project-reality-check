# Contributing to Project Reality Check

Thank you for helping make the skill more accurate and useful.

## Before opening an issue

- Read `SKILL.md` and `EVALUATION.md`.
- Reproduce the behavior in a fresh session when possible.
- State the agent host, model, date, prompt, browser availability, chosen review mode, observed output, and expected behavior.
- Remove customer data, credentials, private URLs, and confidential project details.

## Good improvement proposals

An improvement should identify:

1. the section or rule affected;
2. the concrete failure or ambiguity;
3. a minimal revised rule;
4. the expected observable behavior;
5. an evaluation scenario or regression check.

Avoid requests for vague “better reasoning”, automatic subagents, unconditional approval, unsupported performance claims, or broad frameworks applied without a decision need.

## Pull requests

Keep a pull request narrow and explain why the change improves an observable outcome. Do not modify unrelated wording. Update `EVALUATION.md` when the behavior or its test coverage changes.

The repository maintainer decides what is merged, released, or declined.
